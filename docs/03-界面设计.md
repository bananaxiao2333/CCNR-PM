# 03 · 界面设计

> 工单面板的视觉与交互规范。新增任何界面构件前先读本文。
> 视觉语言与 CCNR-RP 一致（同一套「CCNR:NET 机密终端」调色板），但**代码不互相引用**，
> 本模组自带等价的 `PmTheme` 实现。

---

## 1. 视觉基调

黑白灰军用终端；**只有告警用红**。结构性标签保留英文（`[ CCNR ]`、`// DRAFT`、`STATUS: OPEN`），
内容本地化（类别名、按钮文字、错误提示）。这是这套视觉语言的一部分，不要「顺手翻译」标签。

---

## 2. 主题令牌（`PmTheme`）

颜色一律取自 `PmTheme`，**界面代码里不得出现裸 `0x` 色值**。自检：

```bash
grep -rn "0x[0-9A-Fa-f]\{8\}" src/main/java/com/ccnrcom/pm/client/ | grep -v PmTheme.java
```

应当只剩用于 `#RRGGBB` 解析的 alpha 掩码。

### 主要令牌

| 类别 | 令牌 |
| --- | --- |
| 面板表面 | `OVERLAY` `PANEL_BG` `PANEL_BG_EVEN` `PANEL_BG_ALT` `SURFACE_POPUP` `SURFACE_CONTROL` `SURFACE_CONTROL_HOVER` `SURFACE_INSET` |
| 描边 | `PANEL_BORDER` `PANEL_BORDER_BRIGHT` |
| 遮罩 | `SCRIM` |
| 文本 | `TEXT_PRIMARY` `TEXT_BRIGHT` `TEXT_SECONDARY` `TEXT_DIM` `TEXT_DISABLED` |
| 强调 | `CYAN`(亮) `CYAN_DIM`(灰) `ACCENT_FILL` `ACCENT_FILL_HOVER` `ACCENT_TEXT` |
| 告警 | `RED` `RED_DIM` `RED_LINE` `RED_BG_SOFT` `RED_BG_HOVER` |
| 状态 | `STATUS_OPEN`(红) `STATUS_CLAIMED`(白) `STATUS_CLOSED`(灰蓝) `STATUS_REJECTED`(灰) |
| 滚动条 | `SCROLL_TRACK` `SCROLL_TRACK_ACTIVE` |

### 亮底深字（硬性约束）

本调色板里「强调」= **亮色填充 + 深色字**。任何亮色/白色填充之上的文字**必须**用 `ACCENT_TEXT`：

- 主按钮（`PmButton.Variant.PRIMARY`）
- 选中行（`PmTheme.selectedBar`）
- 下拉当前项（`popupRow(current=true)` → `popupRowText` 已自动返回深色）

新增构件时按三步自检：①这个底是亮色吗 ②字色是深色吗 ③深色字**只**出现在亮底分支吗。

理由：CCNR-RP 修过一次「白底白字」缺陷（v2.24.1），这类错误在深色界面里极易漏看。

**与状态色的冲突怎么解**：`claimed` 的状态色**就是白色**，写到白底上等于看不见。因此定了两条：

| 底 | 状态色怎么用 |
| --- | --- |
| 暗底（列表行、卡片、详情、暗底按钮） | 直接做**文字色** |
| 亮底（选中行、`PRIMARY` 按钮） | **不上文字色**：选中行保持 `ACCENT_TEXT`；亮底按钮把状态色改用在**描边**上 |

`PmButton.draw(...)` 的重载把这条规则写进了代码（亮底分支忽略传入的状态字色），不靠人记。

### 状态色必须真的被用上

`STATUS_OPEN` / `STATUS_CLAIMED` / `STATUS_CLOSED` / `STATUS_REJECTED` 这组令牌**不是配色装饰**：
只要界面上显示状态**文字**，就必须用 `PmTheme.statusColor(...)`（聊天输出在服务端用
`ChatFormatting` 对应一套，见 `PmCommand.statusFormat`）。
用户反馈过「各种状态不好分辨」——根因就是这组令牌只有看板左缘那 3px 色条在用，文字全灰。

## 3. 共享绘制入口

同类构件只能走这些入口，禁止再写 `g.fill` + 裸色值：

| 构件 | 入口 |
| --- | --- |
| 顶层面板 | `PmTheme.terminalFrame` |
| 嵌入式面板 | `PmTheme.terminalPanel` |
| 卡片 | `PmTheme.card` |
| 列表容器 | `PmTheme.listPanel` |
| 列表行 | `PmTheme.listRow` / `rowColor` |
| 选中行 | `PmTheme.selectedBar` |
| 表头分隔线 | `PmTheme.listHeaderRule` |
| 输入/下拉框 | `PmTheme.controlBox` |
| 弹层 | `PmTheme.popupPanel` / `popupRow` / `popupRowText` |
| 遮罩 | `PmTheme.modalScrim` |
| 装饰 | `PmTheme.gridOverlay` / `scanlines` / `cornerBrackets` |
| 多行文本域 | `PmMultiLineEditBox`（模型在 `PmTextBuffer`，断行复用 `wrapText`/`wrapRows`） |
| 命名 | `PmNames.categoryName` / `statusName`（语言键 → 可读文本的唯一入口） |
| 文字 | `PmTheme.wrapText` / `clip` / `wrapRows` / `tag` / `section` |
| 按钮 | `PmButton.draw`（三种变体） |
| 滚动条 | `PmScrollbar.draw` / `clickV` / `dragV` / `endDrag` |

**为什么收口**：CCNR-RP 曾出现同一构件四种画法（列表行），导致悬停/斑马纹行为不一致。
收口后「同类构件只有一种画法」，改一次即全局生效。

## 4. 工单面板布局

```
┌─ [ CCNR ] 举报工单 ─────────────────────── // DRAFT ─┐
│                                                      │
│  // 举报内容                                          │
│  ┌────────────────────────────────────────────────┐  │
│  │ 刚才 Bob 隔着墙把我矿挖了          (EditBox)    │  │
│  └────────────────────────────────────────────────┘  │
│  已从你的 /a 消息自动填入，可直接修改                  │
│                                                      │
│  // 关联玩家（选填）  从在线名单里选，回车/点击确认成胶囊  │
│  ┌────────────────────────────────────────────────┐  │
│  │ ( Bob × ) ( Carol × ) |            (胶囊输入框)  │  │  ← 输入前缀时下方弹候选
│  └────────────────────────────────────────────────┘  │
│  // 举报类别                                          │
│  ┌────────────────────────────────────────────┐ v   │
│  │ 作弊 / 外挂                                │     │
│  └────────────────────────────────────────────┘     │
│  // 详细描述（选填）                                   │
│  ┌────────────────────────────────────────────────┐  │
│  │ 多行文本域（换行、方向键、选区、滚动条）          │  │
│  └────────────────────────────────────────────────┘  │
│  （状态 / 错误区）                                     │
│  [ 取消 ]                          [ 提交举报 ]       │
└──────────────────────────────────────────────────────┘
```

### 尺寸

- 面板宽度：`clamp(380, 窗口宽-40, 560)`
- 面板高度：`clamp(360, 窗口高-40, 480)`

- **关联玩家＝胶囊输入**（`PmChipInput` + 纯模型 `PmChipModel`，v0.11.0 起）：
  输入前缀 → 候选弹层 → **回车/点击确认后变成一个整体** `( Alice × )`；× 删掉、
  文字为空时退格删最后一个胶囊、最多 8 个（`ReportValidator.MAX_TARGETS`）。
  **只能从在线名单里选**：输入框里的文字只是过滤条件，未成胶囊的文字**不会被提交**。
  **过滤文字收任何可见字符**（中文、空格、符号都收，只挡控制字符与 `§`，长度上限 `MAX_TEXT = 32`）——
  0.11.0 曾把它限成玩家名字符，结果中文输入法下「框点得亮却打不进字」，0.12.0 已改正：
  「只收名单里的」是**提交值**的规则，不是**过滤文字**的规则。
  提交值仍是逗号分隔的名字串，因此**协议与服务端校验都没变**（服务端还会再判一次
  「在线 或 本服见过面」，见 docs/02 §4）。
- **详细描述**：`PmMultiLineEditBox`（原版没有多行输入控件，本模组自己实现），一路顶到状态/错误区之上，
  把面板剩余高度全给它。上限配为 0 时控件保留但置灰不可编辑。
- 窗口小于最小值时贴边显示（`min(pw, max(180, width-8))`），避免面板反向溢出到屏幕外

### 纵向布局（相对面板顶边）

| 元素 | 偏移 |
| --- | --- |
| 标题栏 / 分隔线 | +11 / +26 |
| 举报内容 标签 / 输入框 | +32 / +42 |
| 预填提示 | +64 |
| 关联玩家 标签 / 胶囊框 | +80 / +90（框高 **36**＝2 行胶囊） |
| 举报类别 标签 / 控件 | +136 / +146 |
| 详细描述 标签 / 输入框 | +174 / +184 |
| 详细描述框底边 | `按钮顶 - 6 - 34`（把剩余高度全给它） |
| 状态/错误区（顶） | 详细描述框底边 + 4 |
| 按钮行 | 底边内缩 10 |

状态/错误区在按钮行上方自动截断（放不下的行不画），保证**错误提示永远压不到按钮上**。

输入框统一高 `18`（沿用原版 `EditBox` 尺寸惯例）。详细描述上限配为 `0` 时，
控件保留但**置为不可编辑**——栏位突然消失会让人以为界面坏了。

## 5. 交互规范

### 多行文本域（`PmMultiLineEditBox`）

- **断行复用 `PmTextLayout.wrapRows`**，不另写一套——两套断行必然漂移，症状是「画出来的行」与
  「光标所在的行」对不上。
- **始终为滚动条预留宽度**（即使当前不溢出）：否则内容变长时文本会突然变窄、已输入的字跟着重排跳动。
- 文本模型（光标/选区/移动）在 `PmTextBuffer` 纯类里，边界行为由单测钉死（含代理对整体删除、
  软换行边界上的行索引归属）。
- 支持：输入、回车换行、退格、Delete、方向键（Shift 扩选）、Home/End、PageUp/PageDown、
  Ctrl+A/C/X/V、点击与拖拽选择、滚轮与拖拽滚动。
- 编辑器内**不拦 Esc**：Esc 归面板/弹层管，弹层优先规则见下。

### 胶囊输入框（关联玩家）

- **绘制与命中判定共用一处坐标**：胶囊矩形只由 `PmChipInput.chipRects()` 算一次，
  渲染、悬停、点 ×、弹层矩形全用它——两处各算一份就是「看到的 × 和点到的 × 不是一个」。
- **固定 2 行高**：最多 8 个胶囊在窄窗口下会换行，框高固定住，布局不随内容跳动
  （代价是详细描述少 18px，这个交换是值得的）。
- **弹层与焦点绑定**：`PmChipInput.hasPopup()` 要求 `isFocused()`。候选是「我正在这个框里打字」的
  产物，焦点走了弹层还挂着，就会变成「屏幕上一片候选、点哪儿都被它吞掉」。
- **弹层打开时点到别处**：只收起候选（`popupSuppressed`，过滤词保留），这次点击**让给玩家真正点到的控件**
  ——与下方「附加弹层」的「不穿透」不同：候选弹层挂在输入框上，它不该替玩家决定这一下点不生效。
- **输入控件一律自查 `isFocused()`**：原版只把 `charTyped` 发给 `getFocused()`
  （`ContainerEventHandler` 的默认实现就是这一句），但一旦有人直接调进来，
  没有这道检查就会出现「没焦点也在收字」。
- **弹层打开时吞点击、Esc 只关弹层**（**不清掉玩家已输入的过滤词**，下次打字自动恢复）、
  滚轮只滚弹层、最后绘制、溢出可滚轮 + 拖拽并画滚动条。
- **说不清楚的地方要明说**：输入了但没有匹配的在线玩家 → 框内右侧显示「没有匹配的在线玩家」；
  已满 8 人 → 显示「最多 8 人」。否则「打不进去」会被当成界面坏了。

### 下拉选择器 / 补全弹层＝附加弹层

举报类别是手绘的下拉（`controlBox` 显示当前值 + `v`/`^` 展开标记）；
关联玩家则是**输入框 + 补全弹层**（见上节），选中候选只替换「光标所在的那一段」而不是整串。
展开后是一个覆盖在面板之上的弹层（`popupPanel` + `popupRow`）。规则：

1. **打开时吞掉一切点击**：点到行 = 选中；点到其它任何地方 = 只关闭弹层，**不穿透**到下层控件。
   （**例外**：挂在输入框上的候选弹层——如关联玩家的胶囊补全——点到别处时只收弹层，
   点击照常落到玩家点到的控件上，见上节。）
2. **Esc 先关弹层**，再关面板。绝不能一次 Esc 把整个面板关掉。
3. **滚轮只滚弹层**，不让下层跟着滚。
4. **溢出时既可滚轮也可拖拽**，并画出滚动条（`PmScrollbar`）。弹层最多 8 行。
5. 弹层高度会贴住面板底边，**绝不跑出面板**。
6. 弹层必须**最后绘制**，其余元素不得盖住它。

### 状态机

```
编辑中 ──提交──► 等待回包（awaiting：锁表单、Esc 不关面板）──►
   成功 → 显示「已创建工单 #a3f2c1d8」，锁表单，取消按钮变「关闭」
   失败 → 表单保持可编辑，错误逐条显示（红字，按像素断行）
```

等待回包时不允许关面板，否则回包无处显示。成功后锁表单是为了防重复提交。

### 关闭

`onClose()`：清空静态句柄、结束滚动条拖拽、返回 `parent`（打开面板前的界面）。
`isPauseScreen()` 返回 `false`（游戏不因打开面板而暂停）。

## 6. 文本规则

- **一律按像素逐字符断行**（`wrapText`），**禁止按空格断行**。
  中文句子没有空格，按空格断行会把整句当成一个「词」，整行溢出容器并压到按钮上。
- 列表行、id、名字用 `clip` 裁剪并追加 `…`。
- 错误/提示文案走 `wrapText`。

规则由 `PmTextLayout`（纯类）实现，`PmTextLayoutTest` 覆盖了
「中文长句不溢出」「断行不丢字」「省略号不超宽」等场景。

---

## 7. 本地化

- 语言包：`assets/ccnr_pm/lang/zh_cn.json` 与 `en_us.json`，**键集合必须完全一致**。
- 键前缀：`ccnr_pm.<域>.<名>`；界面域为 `ccnr_pm.gui.*`，命令为 `ccnr_pm.command.*`，
  错误为 `ccnr_pm.report.err.*`，类别为 `ccnr_pm.category.<id>.*`。
- 门禁：`LangFileTest` 检查三件事——键集合一致、无「值等于键」的占位翻译、
  内置类别都有名称与描述；另外还校验中英文的 `%s` **占位符数量一致**（否则会抛格式化异常）。
- 类别显示名允许管理员用 JSON 的 `name` 字段写死（语言中立）；
  否则取语言键 `ccnr_pm.category.<id>.name`，缺键时回退显示 id
  （比显示一串红色原始键有用）。

## 8. 左上角常驻工单看板（HUD 浮层）

管理员在线时，左上角**持续**显示当前所有活跃工单（待处理 / 处理中）各一张小卡片。

```
┌──────────────────────────┐  160 × 90（16:9 横版）
│▌他隔着墙把我矿挖了  作弊/外挂 待处理│  ← 左：举报内容；中：类别；右：**状态标签（带色）**
│ 我在矿洞里被他隔墙挖了…       │  ← 详细描述（1~2 行，超出截断补 …）
│   Alice    Bob            │  ← 每个头像上方一个小名字
│   ▣   │   ▢▢              │  ← 头像贴底；竖线分隔「提交者 | 关联玩家」
└──────────────────────────┘
   ▲
   └── 左缘强调条：处理中＝亮色，待处理＝状态色（与右上状态标签同一语义，一个色条一个文字）
```

### 状态必须一眼可辨（用户反馈「不好分辨」）

状态色早就在 `PmTheme` 里（待处理＝`STATUS_OPEN` 红、处理中＝`STATUS_CLAIMED` 亮、
已办结＝`STATUS_CLOSED` 灰蓝、已驳回＝`STATUS_REJECTED` 灰），但**凡是文字出现的地方原来全是灰的**。
现在规则是：**只要显示状态文字，就用 `PmTheme.statusColor` 上色**——卡片右上标签、管理面板列表行、
详情、卡片按钮文案、玩家面板、聊天输出（服务端用原版 `ChatFormatting`，见 `PmCommand.statusFormat`）。

**唯一的例外是亮底**：docs/03 §2 硬性要求亮底用深色字，而 `claimed` 的状态色本身就是白色，
写到白底上会直接看不见。因此**亮底不给文字上色**（列表选中行保持深色字、
亮底按钮把状态色改用在描边上）。这条例外是刻意的，不是漏做。

### 标题行的宽度分配顺序

标题行是「左：举报内容 / 中：类别 / 右：状态标签」三段，空间不够时**让位的顺序是固定的**：

| 优先级 | 元素 | 理由 |
| --- | --- | --- |
| 1（最高） | **状态标签** | 它就是要被分辨的那个东西，必须完整可读 |
| 2 | 举报内容（下限 `MIN_TITLE_W = 46`） | 卡片回答的是「什么事」，不能被挤成看不懂的几个字 |
| 3（最低） | 类别 | 它在工单列表与详情里都还有一份，最先被裁 |

状态标签宽度按**实际文本测量**（中文 3 字 ≈ 27px、英文 "Rejected" ≈ 44px，上限 `STATUS_MAX_W = 44`），
因此换语言不会把布局挤坏。三段宽度之和恒等于内容宽度——`NoticeCardLayoutTest` 用穷举断言钉死「永不重叠」。

画法收在一个共享入口 `TicketNoticeOverlay.renderHeaderRow`：只读浮层与交互看板共用，
否则改一次版式就要改两处，漏一处会出现「同一张工单在两个界面里长得不一样」。

### 卡片上放什么：内容优先，不放编号

**不显示工单编号**。编号对「处理」没有意义——管理员扫看板要回答的是「什么事、谁报的」，
所以放**举报内容 + 类别 + 状态 + 一排头像**。编号只在管理面板里出现（那里要靠它引用工单、执行动作）。

举报内容按像素断行显示两行，超出在末行留出省略号位置再截断（保证「被截断」本身可见）。
服务端会把内容截到 240 字再下发：十几张卡片各拖 4KB 会让载荷大一个数量级，而卡片只显示两行。

### 尺寸与比例（两次返工的教训）

| 版本 | 尺寸 | 问题 |
| --- | --- | --- |
| 初版 | 216×162 (4:3) | 太大，且为填多余高度塞了正文 |
| 二版 | 156×117 (4:3) | 仍偏大；为填高度做了**垂直居中**，看起来「分布奇怪、不靠边」 |
| 三版 | 144×81 (16:9) | 高度随比例收窄，面积降到六成 |
| **现版** | **160×90 (16:9)** | 标题与类别同行分列左右还需要更宽；后又在右侧加入状态标签 |

所有算术集中在纯类 `NoticeCardLayout`，由 `NoticeCardLayoutTest` 钉死：
16:9 精确成立、**宽 ≤164 / 高 ≤94 / 单卡面积上限**（防日后被内容撑回去）、
外边距 ≤4（「不靠边」的回归保护）、标题顶边与头像贴底、正文两行不压头像、
**标题行三段之和恰好铺满且永不重叠**、除竖线外无额外间距、堆叠不重叠、同屏上限 2~6。

### 不再自动消失

**卡片什么时候消失由工单状态决定，不由时间决定**。办结/驳回后服务端不再把它算作活跃，整份看板刷新时它自然离开。
早期版本十几秒淡出，与「持续展示所有活跃未受理工单」的需求直接冲突——管理员低头挖一会儿矿，工单就从视野里没了。

数据流：服务端**整份替换**下发活跃列表（`TicketBoardS2C`）。推送时机＝登录、建单、认领、办结、驳回、
以及头像抓取完成后。整份替换让客户端不可能出现「以为还在看板上、其实早就办结了」。

### 排序与折叠

- **已认领的置顶**（管理员认领过的最该被看见），用稳定排序，同组内保持服务端给的时间倒序，
  因此刷新不会让卡片跳位。
- 同屏最多 **4 张**，超出折叠成「还有 N 张」小条——看板不能铺满屏幕。

### 边界

- **浮层无法点击**：无界面时鼠标被相机抓取、没有光标坐标。处理动作在管理面板与交互看板里做（见 §9）。
- **交互看板打开时不画本浮层**：原版 HUD 是**连 Screen 一起**渲染在最底层的，只读卡片与可点卡片
  会同时画在同一位置、叠成重影（两套几何 `cardY` / `cardYInteractive` 还不一致）。
  因此 `TicketNoticeOverlay.render` 在 `PmBoardScreen` 打开期间直接返回，关掉看板自然回来。
  （早期文档写的是「只在没有打开任何界面时绘制」——Forge 的 `IGuiOverlay` 并不保证这一点，
  这条规则现在由本模组自己实现。）
- 头像优先用服务端下发的 base64（第三方/离线服务器的正解），拿不到回退到客户端解析的皮肤。

## 9. 管理面板与交互看板（`PmAdminScreen` / `PmBoardScreen`）

单屏终端风格、**页签式**。管理面板打开方式：按键 **P**（`IN_GAME` 冲突上下文，可在「控制」里改）
或 `/pm panel` 命令。两条都保留：命令那条让服务端脚本/后台也能给管理员开面板，
按键冲突时也还有退路。

**P 键的两档**（用户要求）：

| 按键 | 界面 | 职责 |
| --- | --- | --- |
| **短按 P** | `PmBoardScreen` 交互看板 | 鼠标出来，卡片与头像可点（认领/关闭/释放、玩家动作） |
| **长按 P（≥600ms）** | `PmAdminScreen` 管理面板 | 列表/详情/备注，完整的工单处理 |

### 为什么管理动作必须放在 Screen 里（重要结论）

通知卡片是 HUD 浮层，**无法点击**——无界面时鼠标被相机抓取，根本没有光标坐标可供命中判定。
所以「认领 / 忽略」这类动作只能落在 Screen 上。两者分工：

| | 通知卡片（HUD 浮层） | 管理面板（Screen） |
| --- | --- | --- |
| 职责 | 抬头看一眼「有工单」 | 动手处理 |
| 能否点击 | **不能** | 能 |
| 出现时机 | 建单后自动淡出 | 按键/命令主动打开 |

### 外壳与页签

面板只提供一个外壳：标题栏（`[ CCNR ]` + 标题 + 右上关闭按钮）、页签条、
输入分发（先给当前页签，再落到 `super`）。内容全部由 `PmTab` 实现承担。

新增页签只需：在 `PmAdminScreen.TABS` 里加一个 id、在构造器里 new 出对应实现、
补一个语言键 `ccnr_pm.gui.panel.tab.<id>`。**不需要动外壳**。

页签不是 Screen，拿不到 `addRenderableWidget`，因此通过
`PmAdminScreen.addPanelWidget` 转交 widget 注册（widget 生命周期只能由 Screen 持有）。

### 工单管理页签（`PmTicketsTab`）布局

```
┌─ [ CCNR ] 工单管理终端 ──────────────────────── [X] ┐
│ [工单管理]                                            │  ← 页签条
│ [全部][待处理][处理中][已办结][已驳回]                 │  ← 筛选
│ ┌─ TICKETS ───────────┐ ┌─ DETAIL ──────────────┐   │
│ │ #a3f2c1d8 待处理     │ │ 工单号：#a3f2c1d8      │   │
│ │ Alice → Bob         │ │ 状态：待处理            │   │
│ │ #7b1e04af 处理中     │ │ 提交者：Alice           │   │
│ │ …                   │ │ 关联玩家：Bob, Carol    │   │
│ └─────────────────────┘ │ 类别：作弊 / 外挂        │   │
│                         │ 举报内容（按像素断行）    │   │
│                         │ [备注输入框]            │   │
│                         └────────────────────────┘   │
│ [ 认领 ]  [ 办结 ]  [ 驳回 ]                          │  ← 动作（按状态禁用）│
└──────────────────────────────────────────────────────┘
```

- 列表行两行制：首行 `举报内容`，次行 `[我的 · ]类别 · 状态 · 提交者 [→ 关联玩家]`；
  **状态词单独上色**（选中行是亮底，按硬性约束保持深色字），且分三段绘制、给状态预留宽度——
  前缀被裁也要保住状态，类别与关系最先让位。选中行用 `selectedBar` 亮底 + 深色字。
- 详情按字段逐行绘制，正文与描述走 `wrapText`；空间不足时截断，绝不压到备注框上。
  「状态：」的值用状态色。
- 按钮按状态禁用（认领只对「待处理」有意义，办结/驳回只对「未办结」有意义），
  **但禁用只是体验**——真正的判定在服务端，被改造过的客户端直接发动作包也会被拒。
  **文案也按动作的结果状态上色**（认领→处理中、办结→已办结、驳回→告警红），与交互看板的卡片按钮同一套语义。
- 备注在切换选中行时会**保留**（切换会触发一次重建，若置空就等于把管理员打的备注擦掉）。

### 数据流向与「服务端权威」

```
打开面板 → C2S RequestTicketsC2S(filter, page)
切换筛选 → C2S RequestTicketsC2S(...)
点击动作 → C2S TicketActionC2S(action, id, note)
             ↓ 服务端：权限重校验 → 状态机判定 → 落库
           S2C AdminResultS2C(ok, errKey)
           S2C TicketListS2C(权威快照)   ← 成功时紧接着推一份
```

**客户端从不自己改本地列表**：认领成功后不手动把状态改成 claimed，而是等服务端回推快照。
否则「本地显示已认领、服务端其实没认领」这类不一致永远无从察觉。

### 交互看板（`PmBoardScreen`，短按 P）

**不画背景**（游戏画面照常可见），语义就是「鼠标出来了、左上角卡片多了一排按钮」。
卡片与只读浮层**共用同一套 `NoticeCardLayout` 几何**，切过去时位置不跳；
而打开期间只读浮层**停止绘制**（见 §8 边界），否则两者叠成重影。

```
┌ 左上：活跃工单卡片（每张底部一排按钮）
│
│                                            ┌── 右键头像弹出的快捷菜单（弹层）
│                                            │ Alice          复制
│                                            │ 把玩家传送过来
│                                            │ 传送到该玩家
│                                            │ 刷出玩家
│                                            │ 刷出并传送至此
└───────────────────── [打开工单管理面板]     │ 送回阴间
                       [打开 CCNR-RP 面板]   └──
```

| 元素 | 位置与行为 |
| --- | --- |
| 卡片右上 | **带色状态标签**（宽度分配顺序：状态 → 标题 → 类别，见 §8） |
| 卡片底部按钮 | **待处理**＝`认领`/`忽略`；**处理中**＝`关闭`（结束工单）/`释放`（驳回）；**文案按动作的结果状态上色**（关→已办结、释→已驳回、领→处理中；亮底走描边） |
| 快捷按钮 | **右下角**（用户指定）：工单管理面板（始终有）＋ CCNR-RP 管理面板（装了才有，排在上方） |
| 头像**左键** | 把该玩家**传送过来** |
| 头像**右键** | 打开**快捷菜单**（弹层） |
| 头像**悬停** | 描一圈亮框——「这里可以点」这件事必须自己说出来 |

按钮矩形由 `pmButtonRect()` / `rpButtonRect()` 统一给出，**绘制与命中判定共用同一处**：
两处各算一份坐标正是「按钮画在这里、点在那里」的经典成因。

**快捷菜单（弹层）**：

- 首行是**玩家名**（亮底深字，一眼看出点的是谁），右侧小字提示「复制」；
  点它把 `名字 (UUID)` 放进剪贴板，并在动作栏回显——剪贴板是**看不见**的，没有反馈等于让人不确定复制了没。
  手输的离线关联玩家没有 UUID，就只复制名字（凭空编一个 UUID 粘进命令里只会更糟）。
- 其余五项：把玩家传送过来 / 传送到该玩家 / 刷出玩家 / 刷出并传送至此 / 送回阴间。
- **装了 CCNR-RP**：两个「刷出」先向服务端要角色列表，弹**可滚动的角色选择器**；
  部署走对方唯一的入口，并且**强制跳过入场演出**（开场黑屏 / 左下角电影 HUD / CMDCam 场景动画，
  由 `SKIP_CINEMATIC` + `NO_MUSIC` 一次覆盖，直接落位切生存）——管理员刷人不需要看演出，
  而且这只作用于这一次部署，玩家自己部署时的演出不受影响（见 `integration.RpBridge`）。
  「送回阴间」走对方的退场清理（观察者 + 清背包 + 卸属性，不生成遗体）。
- **没装 CCNR-RP**：「刷出玩家」＝**冒险模式**；「送回阴间」＝**旁观模式**。

**几何与弹层规则**（`PmPopupLayout`，纯类，8 例单测）：

- 最多 **8 行**，超出可滚轮 + 拖拽并画滚动条；屏幕比 8 行还矮时**按屏幕收行数**
  （溢出到屏幕外的行既看不到也点不到）。
- 以鼠标为锚点向右下展开，**碰到边缘向反方向翻**，绝不跑出屏幕。
- 弹层打开时吞掉一切点击（点到别处只关弹层、**不穿透**到下层卡片）、Esc 先关弹层、
  滚轮只滚弹层、**最后绘制**。

**头像命中几何收在纯类 `BoardAvatarLayout`**：绘制与命中判定共用同一套坐标，
否则会出现「点左边的头像弹出右边玩家的菜单」——只在特定名字长度/关联人数下复现，极难查。
溢出时**少画的那个头像不留可点区域**（看不见却能点等于随机点到别人）。

**动作结果与服务端权威**：客户端只发意图，服务端重新鉴权、重新解析目标（离线即回绝），
结果用系统消息回给管理员。看板内容仍只由服务端下发的整份快照决定。

## 10. 新增界面构件的检查清单

1. 颜色是否全部取自 `PmTheme`？跑一遍第 2 节的 grep 自检。
2. 是否复用了共享绘制入口，而不是自己 `g.fill`？
3. 亮底是否用了 `ACCENT_TEXT` 深色字？
4. 溢出的列表是否**既能滚轮也能拖拽**并画了滚动条？滚动条 id 在**本界面内**唯一？
5. 若是弹层：打开时是否吞掉点击、Esc 是否只关弹层、是否最后绘制？
6. 文案是否走 `wrapText`/`clip`，而不是按空格断行或直接溢出？
7. 新增文案是否**中英文都加**了，且 `%s` 数量一致？
8. 是否破坏了「只改视觉」原则（样式调整不得顺带改布局/命中判定/行为）？
9. 输入类控件的**字符规则**是否只挡控制字符？过滤/搜索文字**不要**限制成业务字段的字符集
   （限成玩家名 ⇒ 中文输入法下打不进字，见 §5「胶囊输入框」）。
10. 输入类控件是否自查 `isFocused()`？它的弹层是否也绑定焦点（失去焦点即消失）？
11. `init()`（窗口缩放/资源重载会重新调用）之后，焦点是否搬到了**重建后的**控件上？
    焦点留在旧实例上，症状与「打字没反应」一模一样。


**两个必须记住的坑**：

1. `JAVA_HOME` 不导出会用系统 JDK（Zulu 26）导致构建失败。
2. **`build` 不跑测试**（`onlyIf { hasProperty('runTests') }`）。验收必须显式 `-PrunTests`。

## 2. 开发纪律

### 先读后写、修根因

动工前先读目标代码及相邻的注册/事件/网络/配置/生命周期代码。
按「现象 → 调用链 → 根因 → 影响面 → 最小改动 → 实现 → 验证」推进。

**禁止**用强制刷新、重复发包、每帧重建、延时重试掩盖状态错误。
兜底逻辑必须有边界、去重、限频。

### 服务端权威

服务端是状态最终权威，客户端只发意图。服务端必须**重新校验**距离/权限/目标/参数/世界有效性。
本项目的具体体现：`ReportValidator` 被客户端与服务端**共用同一实现**，服务端还额外核对在线状态、
冷却、并发上限。

### 线程边界

独立线程只碰纯数据/不可变快照；Level/NBT/网络/渲染必须回主线程；禁止每实例一线程。
`ccnr-pm-db-writer` 线程只能跑 JDBC。

### 对称清理

资源/线程/监听器/网络追踪/缓存必须对称创建释放。
世界卸载、维度切换、配置重载、服务端停止、断线都是必做清理路径。
本项目：`ServerStoppingEvent → TicketService.shutdown()` 排空写队列并断开连接。

### 配置开关必须真正改执行路径

关闭了就不该继续算。本项目的 `db.enabled` 真正切换后端，不是只影响日志。

### 质量与交付

- 编译通过 ≠ 正确。**未验证的必须明说**（见第 6 节）。
- 无占位、空壳、伪异步、只为过编译的假逻辑。
- 保留未被需求否定的原行为。接管 `/a` 时管理员的路径必须与原 CCNR-Com 行为一致。
- 提交前查 `git diff`，单一职责。
- 文档写「为什么 / 边界 / 如何失效」，不只写「是什么」。

## 3. 代码风格

- 格式化唯一入口：`./gradlew spotlessApply`（palantirJavaFormat + MIT 许可证头）。
  不要手工调格式，也不要为格式争论。
- 编译带 `-Xlint:all`，警告不阻断构建但要当回事。
- 纯类（无 MC import）优先：能离线单测的逻辑尽量放进 `ticket` / `data` / `client.ui.PmTextLayout`。
- 注释解释**为什么**与**边界**，不复述代码。

## 4. 网络与持久化约定

### 包

- 新增包**只能追加在 `PmChannel.register()` 末尾**——注册顺序即协议编号，插在中间会让已发布客户端错位。
- 长度上限声明为常量，**编解码共用**。不匹配会造成缓冲区错位且不报错。
- S2C 用 `DistExecutor.unsafeRunWhenOn(CLIENT, () -> () -> ...)` 保护；C2S 不需要。
- 处理器注册为 `consumerMainThread`（它内部已做 `enqueueWork` + `setPacketHandled`，
  处理器里**不要**再调一次）。

### 持久化

- JSON 一律走 `JsonUtil.atomicWrite`（`.tmp` + `ATOMIC_MOVE`），损坏时留 `.bak` 并继续。
- 数据库标识符一律经 `SqlDialect.quote`，**绝不拼接用户输入**（玩家填的内容只以绑定参数进入语句）。
- 多条语句的写必须用 `Database.tx`，不要自己写 `setAutoCommit` 而漏掉 rollback。
- 存储选择用 `Database.usable()`，**不要**用 `enabled()`（前者含「真的连上了」）。

## 5. 界面规范

完整规范见 [docs/03](03-界面设计.md)。硬性几条：

1. 颜色/描边/遮罩/行底只能取自 `PmTheme`，**禁止裸 `0x` 色值**。
2. 同类构件只能走共享入口（`listRow` / `popupPanel` / `modalScrim` / `PmButton.draw` …）。
3. 亮底必须用 `ACCENT_TEXT` 深色字。
4. 文案按像素逐字符断行（`wrapText`），**禁止按空格断行**（中文会整行溢出）。
5. 弹层三条件：打开时吞掉点击、Esc 只关弹层、关闭时清理专属 widget。
6. 溢出区域必须既能滚轮也能拖拽，并画滚动条。

## 6. 验证要求

### 每次改动

- `./gradlew build`（含 `spotlessCheck`）
- `./gradlew test -PrunTests`

### 新增功能

- 纯逻辑必须有单测。当前 241 个用例覆盖：校验规则、类别注册表、排序全序性、SQL 方言、
  文件存储端到端（落盘/重开/标识延续/损坏恢复）、文本断行、弹层与看板几何、
  语言包一致性、网络包注册与动作分支接线。
- 涉及网络包的改动，必须同时更新本文档与 `docs/00 §7` 的协议表。
- 涉及界面，按下 `docs/03 §8` 的清单自查。

### 启动期静态初始化（v0.1.0 踩过的坑）

`ExceptionInInitializerError` 是**编译期与常规单测都拦不住**的一类缺陷：
静态初始化只在类首次被主动使用时执行，所以「编译通过 + 既有测试全绿」完全不能说明
模组能起来。v0.1.0 就是因为 `PmConfig` 的 `ForgeConfigSpec.Builder` 多弹了一层上下文，
导致模组一启动就加载失败。

因此约定：**凡 `<clinit>` 会在模组构造期执行的类，必须在 `StartupSmokeTest` 里被真正初始化一次。**
新增这类类时同步补进去。

### 服务端权威（约定 + 门禁）

**约定**：任何来自客户端的输入都只是「意图」，服务端必须重新判定。UI 上的约束
（输入框 `maxLength`、下拉候选、本地预校验）**一律不是安全边界**。

**门禁**：`ServerAuthorityTest` 把这条约定固定成会失败的断言——
C2S 包不得携带身份字段、`ReportValidator.validate` 签名里不得出现 boolean 开关、
被改造过的客户端送来的超量/超长/非法类别草稿必须被拒。
`SubmitGateTest` 钉死防刷闸门的边界（冷却到期、并发上限的 `>=` 与 `>`）。

新增任何 C2S 包或提交字段时，必须同步更新 `docs/02 §4` 的权威链审计表，
并确认新字段在服务端被重新校验。

### 禁止起服务器（用户要求）

**不得**用 `./gradlew runServer` / `runClient` 或任何 Minecraft 进程做验证。
运行时行为一律由用户实机确认。

这条禁令的实际后果是：**易错的运行时逻辑更必须被抽成纯类并写测试**，而不是靠"起一次服务看看"。
本仓库已经这样做的部分：

| 纯类 | 覆盖的运行时风险 |
| --- | --- |
| `ReportValidator` | 提交校验（客户端与服务端共用一份） |
| `SubmitGate` | 防刷闸门边界（差一位就锁不住人或挡住正常玩家） |
| `TicketId` | 标识前缀匹配、大小写/连字符归一化 |
| `TicketPage` | 面板数据编解码往返与坏输入降级 |
| `NoticeCardLayout` | 通知卡片几何（4:3、内容不贴边、头像容量） |
| `SkinUrl` | 皮肤 URL 解析与协议白名单 |
| `PmTextBuffer` / `PmTextLayout` | 多行编辑器的光标/选区与断行 |
| `PmPopupLayout` | 弹层几何（最多 8 行、按屏幕收行数、靠边翻转、绝不溢出） |
| `BoardAvatarLayout` | 看板头像槽位（绘制与命中共用坐标，溢出不留可点区域） |
| `ProfessionRef` | 外部模组（CCNR-RP）角色列表的编解码与坏输入降级 |
| `Database` + `JdbcTicketStore` | **真实 SQLite**（含 v2→v3 迁移阶梯） |
| `StartupSmokeTest` | 构造期静态初始化崩溃（曾导致模组加载失败） |

仍只能由实机验证的部分（不要假装覆盖）：网络通道的静态初始化（`PmChannel.<clinit>` 需要真实
Forge 网络栈）、任何界面渲染与鼠标交互（含右键菜单与滚动条拖拽）、与 CCNR-Com 的命令接管联调、
头像 HTTP 下载链路、**与 CCNR-RP 的反射联调**（对方装没装、签名变没变、素材未同步时的失败路径
——这些在离线单测里没有真实对端，只能靠实机）。

### 哪些**没有**被自动化验证（必须人工确认）

- **实际游戏内行为**：面板渲染、鼠标/键盘交互、下拉弹层、提交往返。
  历史上做过几次启动验证（v0.1.0 在此暴露了静态初始化崩溃，v0.2.0 修复），
  但**现已禁止起服务**，此后运行时行为一律由用户实机确认；**完整交互流程仍未验证**。
- **网络通道的静态初始化**：`PmChannel.<clinit>` 需要真实 Forge 网络栈，纯单测跑不了（见上）。
- **与 CCNR-Com 的联调**：命令接管依赖 `RegisterCommandsEvent` 的执行顺序
  （我们 `LOWEST`、对方默认 `NORMAL`）与 Brigadier 同名节点覆盖行为。
  这一路径**只在真机上验证才算数**：需要同时装 CCNR-Com 与 CCNR-PM，
  分别用管理员账号与普通玩家账号执行 `/a 测试` 与 `/admin 测试`。
- **SQLite / MySQL 后端**：`JdbcTicketStore` 只做了编译与 SQL 生成层面的测试，
  **未对真实数据库执行过**。首次启用数据库时请用 `/pm status` 确认后端为 `sqlite`/`mysql`
  且 `ping` 正常，并提交一条工单验证落库。
